# 前端表格与图表：好看、简洁、稳定、快

两者的难点是**同一个**：**别抖**。表格抖在列宽和滚动位置，图表抖在加载后的高度和重绘。
剩下的（好看、简洁、快）都是收尾。不先把"不动"做到，怎么调样式都不对。

---

## 施工路径：接到任务后按这个顺序走

下面十四节是**知识**；这一节是**做法**。不要从 §1 开始读着写，按这个顺序做。

### 第 1 步 · 先问三个问题，别急着写代码

| 问 | 答案决定 |
|---|---|
| **一次最多渲染多少行 / 多少点？** | §0 的整体方案（普通渲染 / 虚拟滚动 / 服务端） |
| **要回答什么问题？** 精确值 / 趋势 / 比较 / 构成 / 分布 / 相关性 | §3 选表格还是图表、选哪种图 |
| **数据从哪来，可能有多脏？** | §9 的防御强度；是否要报告被忽略的记录 |

这三个问题**任何一个答不上来，就先问用户**，不要替他假设。假设错了，后面全白做。

### 第 2 步 · 选型（§3 §4 §10）

先定"表格还是图表"，再定具体类型，最后定技术：**点数 ≤ 1–2k 用内联 SVG，更多用 Canvas**。
柱和线要同图？先确认它们**同量纲**（§10），不同量纲就拆图，不允许加第二 Y 轴。

### 第 3 步 · 搭骨架，让数据先正确显示

**先不管样式。** 顺序是：数据结构 → 计算（比例尺、刻度、堆叠、分箱）→ 渲染。

- **把计算写成纯函数**：数字进、数字出，不碰 DOM。这样它可测，也就能真的被测。
- **容器高度先固定**（§5），不要让内容撑开它。
- 骨架见下面的「最小骨架」。

### 第 4 步 · 逐条加固（§1 §6 §9）

按这个优先级，因为它们造成的损害依次递减：

1. **不误导**（§6）—— 柱状/面积从 0；折线可以自适应；不搞双轴、3D、超 5 类饼图。
2. **不抖**（§1 §5）—— 列宽显式、行高固定、容器预留空间、网格淡而稳。
3. **不崩**（§9）—— 脏值剔除并计数、时间排序、**缺口断开**、退化域不除零、超量降采样。

### 第 5 步 · 加交互（§8 §10）

**顺序不能反**：先让**悬停给出完整读数**，再决定要不要点击钉住、刷选、联动。
判据是"什么都不点，能不能读到任意一点的**全部字段**"。

### 第 6 步 · 最后做视觉（§11）

排版层次 → 留白与对齐 → 配色主次 → 细节完成度。
**放到最后**是因为前三步会改动尺寸和对齐；先做视觉等于白做两遍。

### 第 7 步 · 自检（§12）

逐条过。**三个必做**：真机滚动、喂脏数据、按最终显示尺寸看。

### 第 8 步 · 交付时说清楚

- 数据里哪些是**模拟**的；
- **忽略了哪些记录**、为什么（§9 的计数要露出来）；
- 哪些地方**没验证过**（例如"我没在 Safari 上试过 sticky"）。

## 最小骨架

一个合格的图表，计算与渲染是分开的。这是最小形态：

```js
// 1) 计算：纯函数，可在 node 里单测，不碰 DOM
export function prepare(rows, { max = 700 } = {}) {
  const clean = rows.filter(r => Number.isFinite(r.value) && Number.isFinite(r.t))
  const rejected = rows.length - clean.length
  const sorted = clean.slice().sort((a, b) => a.t - b.t)
  const points = sorted.length > max ? downsampleByTime(sorted, max) : sorted
  const lo = Math.min(...points.map(p => p.value))
  const hi = Math.max(...points.map(p => p.value))
  const domain = hi - lo > 1e-9 ? [lo, hi] : [lo - 1, hi + 1]   // 退化域不除零
  return { points, domain, rejected, sampled: points !== sorted }
}

// 2) 渲染：把数字放进 SVG，又薄又笨
export function render(host, rows, options = {}) {
  const { points, domain, rejected } = prepare(rows, options)
  // 固定容器高度（§5）：先占好位置，加载不会推挤页面
  host.style.height = `${options.height ?? 260}px`
  // …比例尺、刻度、path…
  if (rejected) console.info(`ignored ${rejected} unusable rows`)   // 丢数据要让人看见
}
```

**检查它是否合格**：把 `prepare` 拿到 node 里跑一组脏数据（`NaN`、乱序、全同值、空数组），
它应该**不抛异常**，并且告诉你丢了几个。做不到就说明计算还没抽干净。

## 知识：十四节

下面从 §0 开始是**规则与依据**。施工时按上面的顺序取用即可。

## 0. 表格：先定规模，再谈方案

**先问：一次最多渲染多少行？** 过度工程和工程不足一样糟。

| 一次渲染的行数 | 方案 |
|---|---|
| ≤ 100 | **普通渲染**，不要虚拟滚动 |
| 100 – 1,000 | 虚拟滚动 + **固定行高** |
| 1,000 – 10,000 | 虚拟滚动 + **服务端分页/排序/过滤** |
| > 10,000 | **服务端承担一切**，或改用内置虚拟化的重量级网格 |

1,000 与 10,000 是两道实测的性能墙。headless 方案（TanStack Table，约 9KB）适合 ≤10k 行
且要自绘 UI；内置虚拟化的网格（AG Grid，约 150KB）适合 100k+ 行。

## 1. 表格稳定：滚动时什么都不跳

| 症状 | 成因 | 对策 |
|---|---|---|
| **列宽随滚动左右跳** | `table-layout: auto` 按**当前渲染的行**推导宽度，虚拟滚动每次换行集就重算 | **`table-layout: fixed`** + 每列显式宽度 |
| 数字列宽度忽宽忽窄 | 比例字形下 `1` 与 `8` 宽度不同 | **`font-variant-numeric: tabular-nums`** |
| 滚动条出现/消失时抖动 | 滚动条占宽度 | **`scrollbar-gutter: stable`** |
| **滚动突然跳回** | `content-visibility: auto` 靠"记住上次尺寸"；DOM 重建时记忆丢失，退回固定的 `contain-intrinsic-size` → 行高塌陷 → `scrollHeight` 变小 → 浏览器强制 clamp `scrollTop` | **固定行高**；且让它与真实行高一致 |
| 数据到达后列宽重排 | 骨架屏与真实内容列宽不同 | 骨架屏**复用同一套列定义** |
| 粘性表头下内容透出 | 表头背景透明 | 表头**必须**不透明底色（深浅两套） |
| Safari 上粘性表头快滚抖 1–2px | WebKit 怪癖（Chrome/Firefox 正常） | 别在 sticky 元素上叠 `transform` |

**两条诊断捷径**：

- **手动拖一下列宽就永久不再抖** → 病根一定是 `table-layout: auto`（拖拽把宽度固定了）。
- **行数少时正常、超过某阈值才开始抖** → 同一处，阈值就是"开始虚拟化"的点。

### 两条明令禁止（会伤到可访问性，不是风格问题）

| 不要 | 为什么 |
|---|---|
| **不要给表格列宽做动画**（`transition: width`） | 每一帧都触发整表重排，是性能灾难；排序/hover 的过渡只动**背景色** |
| **不要在 `<thead>/<tbody>/<tr>` 上用 `display: contents`** | 会破坏辅助技术的表格解析，屏幕阅读器读不出行列关系 |

### `content-visibility` 与虚拟滚动**互斥**

两者都在解决渲染量，叠加零收益却引入上面那条塌陷。要虚拟滚动就别用它；不虚拟化时可用，
但 `contain-intrinsic-size` 必须贴近真实高度。

## 2. 表格：简洁与尺寸

**删掉**：所有竖线、**斑马纹**（用行 hover 代替）、逐格边框、表头下的粗横线。
**保留**：行 hover 底色、极浅的行分隔线或干脆不要、靠**字重 + 字色**区分表头。

| 内容 | 对齐 |
|---|---|
| 文本 | 左 |
| **数字** | **右** |
| 状态 / 标签 / 图标 | 居中 |

| 项 | 紧凑 | **常规（默认）** | 宽松 |
|---|---|---|---|
| 行高 | 32px | **48px** | 56px |
| 单元格纵向 padding | 4px | **12px** | 16px |
| 单元格横向 padding | 12px | **16px** | 20px |
| 字号 | 13px | **14px** | 14px |

> 这组数字不是估的：**Carbon、Polaris、Atlassian、Ant Design 四个系统在"默认 48px 行高、
> 12/16px padding、13–14px 字号"上一致**。
> **"紧凑"是给分析型仪表盘的特例，不是默认** —— 早先版本的 36px 行高 / 8px padding
> 其实属于"很紧凑"，当默认用会让表格显得拥挤。

"好看"几乎全部来自**一致的节奏**，不是任何单点装饰。

**色彩走语义 token**（`--table-border` / `--table-header-bg` / `--table-row-hover` /
`--table-row-selected` / `--table-focus`），深浅两套都要给。

### 无障碍契约（几条硬性的）

表格最容易在这里失分，因为它看起来"只是个表格"。以下来自 WAI-ARIA 与四家设计系统的一致要求：

| 要求 | 为什么 |
|---|---|
| `<table>` 必须有 **`<caption>`** 或 `aria-label` | 屏幕阅读器靠它播报"这是什么表" |
| 每个 `<th>` 都要 **`scope="col"`** | 缺了它 AT 无法按列导航 —— **最常被漏掉的一条** |
| 可排序列要有 **`aria-sort="ascending\|descending\|none"`** | 只画一个箭头图标，辅助技术完全感知不到 |
| 选中行要在 `<tr>` 上写 **`aria-selected="true"`** | 只用 CSS class 表示选中，AT 看不见 |
| 横向滚动容器要有 **`tabindex="0"`** | 否则键盘用户根本无法横向滚这张表 |
| 静态表格用 `role="table"`；**只有单元格可交互**才用 `role="grid"` | `grid` 会启用单元格级方向键导航，给只读表格加它反而添乱 |

**键盘契约**（`role="grid"` 时，引自 [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)）：
`←/→` 同行移动 · `↑/↓` 同列移动 · `Home`/`End` 行首行尾 · `Ctrl+Home`/`Ctrl+End` 表首表尾 ·
`Enter`/`Space` 激活单元格内控件 · `Tab` 移出表格。

**不要用 `<div>` 搭表格**，除非同时补齐 `role="table"` 与 `role="row"` / `role="columnheader"` /
`role="cell"` —— 缺了它们，屏幕阅读器读不出任何行列关系。

## 3. 图表：先问它回答什么问题

**表格给精确值，图表给形状。用错工具，两边都白做。**

| 要回答的问题 | 用 | 注意 |
|---|---|---|
| 精确值是多少 | **表格** | — |
| **趋势 / 走势** | **折线** | 可以从非 0 起（见 §6） |
| 比较大小 | **柱状** | **必须从 0** |
| 部分-整体 / 构成 | 堆叠柱、面积 | **必须从 0** |
| 分布 | 直方图、箱线 | 别用折线画分布 |
| 相关性 | 散点 | — |

**不要用表格表达趋势**（那是把形状塞进格子），**也不要用图表表达精确值**（读不出来）。

## 4. 图表：技术选型

| 方案 | 适用 | 代价 |
|---|---|---|
| CSS / HTML | 进度条、单组简单柱 | 表达力有限 |
| **内联 SVG** | **≤ 1–2k 点**，需要交互或可访问性 | DOM 节点多，几千个后开始卡 |
| **Canvas** | **> 2k 点**、高频重绘 | 无 DOM 语义；**必须自己处理 DPR** |
| 图表库 | 缩放、刷选、联动等复杂交互 | 包体积与配置复杂度 |

**SVG 与 Canvas 的分界在数据点数量**，不在"哪个更现代"。折线图几百个点用 SVG 更好
（可选中、可加 `title`、可打印）；上万点必须 Canvas。

## 5. 图表稳定：**预留空间**

| 症状 | 成因 | 对策 |
|---|---|---|
| **数据到达后整页跳** | 容器高度由内容决定 | **预留空间**：固定高度或 `aspect-ratio`，骨架屏用**同一高度** |
| **高分屏上模糊** | canvas 没乘 `devicePixelRatio` | `canvas.width = cssW * dpr`，再 `ctx.scale(dpr, dpr)`；CSS 尺寸保持 cssW |
| 轴标签位数变化 → 绘图区变宽变窄 | 标签宽度不定 | 轴宽**预留固定值** + `tabular-nums` |
| Y 轴范围随数据变 → 图形跳 | 自动缩放 | 固定域；或对域变化做**平滑过渡** |
| 窗口 resize 时抖 | 每次事件都重建 | `ResizeObserver` + `requestAnimationFrame` 节流 |
| 多个图不同步 | 各自缩放 | **共享 Y 域** |

**验收指标**：布局偏移是**可测量**的（Cumulative Layout Shift）。图表加载后的 CLS 应接近 0 ——
这意味着容器高度在数据到达前就已确定。

## 6. 图表正确：别误导

### Y 轴要不要从 0 —— 两个方向都会错

按 Carbon 设计系统（IBM）的规范：

- **必须从 0**：**柱状图、面积图**（部分-整体、比较）。截断 Y 轴会**放大微小差异**，
  让不重要的差别看起来显著。
- **可以从非 0**：**折线图、散点图**。它们表达**趋势而非相对大小**，对截断不敏感；
  反过来，强行从 0 会把真实波动压成一条平线。

**判据一句话**：**图形面积代表数量 → 从 0；图形只代表位置 → 不必从 0。**

### 其他常见误导

| 不要 | 原因 |
|---|---|
| **双 Y 轴** | 暗示两个序列相关，而相关性是画出来的，不是数据里的 |
| **3D** | 透视让读数失真，无任何信息增益 |
| **饼图超过 5 类** | 人眼分辨小扇区角度很差；改用柱状或堆叠条 |
| 面积图**叠加**比较不同序列 | 下面那条被遮住的部分无法读；要么分组，要么用折线 |
| 分类色超过 **6–8 种** | 颜色不再可区分；换分面或分组 |
| 只靠颜色区分序列 | 色觉差异者读不出；同时用线型、标记或直接标注 |
| ★ **曲线平滑（spline / "自然"插值）** | 曲线会在**两个数据点之间造出并不存在的高低起伏**。数据若本身连续（温度），平滑尚有理由；若是离散采样（月度销量），平滑就是在编故事。**直线最诚实** |

### 实线是采集，虚线是推测

一旦图上出现**估算、预测、插值补出的值**，就必须让读者分得清哪一段是实测的。
唯一可靠的做法是**线型**：

- **实线** = 真实采集到的数据
- **虚线** = 推算、预测、为连续性补出来的部分

**并在切换处标注**（"以下为预测"）。用颜色深浅区分是不够的——那对色觉差异者无效，
而且深浅在不同主题下会反过来。

同理，**如果数值在某点之后变成预测，要用高亮范围把那段区间框出来**，
而不是只换一条线的颜色。

### 折线要不要延伸到 0（或 100%）

§6 说过"折线可以从非 0"。这里补一层更细的判断：

- **数据本身就贴近 0** → **把基线延伸到 0**。此时读者不仅比较两点之间的垂直距离，
  还能比较它们离零有多远，信息更完整。
- **展示的是份额（百分比）且贴近 100%** → **延伸到 100%**，同样的道理。
- **数据在中间区间波动**（如 60–100 的健康分）→ 保持自适应，否则波动会被压平。

**判据**：**零（或 100%）本身是不是一个有意义的参照点？** 是，就画出来。

## 7. 图表：性能与可访问性

**性能**：数据点 > 2k 用 Canvas；**画不出来的点不必画**（先降采样再绘制）；
别在滚动或动画回调里重绘；`ResizeObserver` 里只重设尺寸、不重建数据。

**可访问性**：图表**必须**有文字等价物 —— 最实用的做法是**旁边配一个表格**（表格与图表
在这里正好互补）；不要只靠颜色；如果图表可交互，键盘也要能到达；动画要短（≤200ms）并
尊重 `prefers-reduced-motion`。

## 8. 图表交互：让图不只是"看"

静态图只回答"大概什么样"。一旦要**回答具体问题**，就需要下面这几件 —— 每件都有坑。

| 交互 | 做法 | 坑 |
|---|---|---|
| **hover 读数** | 十字准线 + tooltip，在**数据点里找最近的一个**，不要按像素距离找 | ★ **悬停必须给出完整读数**，不能只给一个概览值 —— 见下面「悬停是获取数据的方式」；tooltip 用绝对定位的 **HTML**，不要画进 SVG（非等比拉伸会让里面的文字横向变形）；靠近右边缘时要翻转方向 |
| **区间选择（brush）** | `mousedown` 记起点、`mousemove` 画选区、`mouseup` 应用 | **必须有最小宽度阈值**（如 <6px 视为点击而非选择），否则一次误点就把视图缩没了；**双击清除**是必须留的退路 |
| **多视图联动** | 一个**派生函数**（如 `selected()`）产出过滤后的数据，所有视图都从它取 | 各视图各自过滤 = 迟早不一致。**一个状态，多处渲染** |
| **序列切换** | 按钮 + `aria-pressed`，重绘 | 隐藏序列后 **Y 域要跟着重算**，否则图看起来像空的 |
| **键盘可达** | 方向键平移 / 缩放选择窗；容器可聚焦 | 鼠标能做到的，键盘至少要能等价做到 |
| **点击选中** | 点击切换选中态，与 hover 分成**两个独立样式**；再点/点空白/Esc 都能清除 | 见 §10 —— 它和悬停是两件事，少一件都像"点了没反应" |
| **悬停高亮的形式** | **必须匹配图表类型**：柱状图用整列色块，**折线 / 散点用细的竖直引导线 + 放大的数据点** | ★ 在折线图上铺整列色块，等于用柱状图的语法讲折线图的故事：它暗示"列"才是数据单位，而且**盖住读者正要看的那个形状** |

**别把 fill 用的 token 当成高亮色。** 一个本来就是半透明的填充色，再叠 `opacity` 会更实、
更重 —— 悬停需要的是一条**细线**（1px 虚线即可），不是一块**面**。面留给"钉住"，
因为钉住本来就该持久、醒目、能当锚点。

**三态齐全**：图表的**加载态 / 空态 / 正常态**都要有。骨架屏的高度与真实内容**一致**
（这就是 §5 的预留空间，同一件事）；空态要说明**为什么空** —— "所选区间无数据"和"出错"
是完全不同的两件事，不能都显示空白。

**降采样**：原始点画不出来时（>2k），**按时间桶聚合**再画 —— 5000 条原始记录按小时聚成
几百点，是常规做法。**表格继续显示原始记录**，图表只负责形状。这是 §3 那个分工的又一处体现。

**派生序列**（移动平均、累计值…）：用**线型**（虚线）而不只是颜色来区分，并且**与原序列
共用一个 Y 域**，否则两条线的相对高度没有意义。

## 9. 脏数据：真实数据一定比示例脏

示例数据是等间隔、无缺失、数值干净的。真实数据三样都占不全。下面每条都来自一次
**两组实现对跑**的实测（朴素写法 vs 加固写法，9 个病态数据集，朴素版在 4 个上失败）。

| 病态 | 朴素写法的后果 | 对策 |
|---|---|---|
| **含 `NaN` / `null` / 字符串** | `Math.min` 拿到非数字 → **整个域变成 `NaN`**，图直接消失 | **先过滤非有限值并计数**，在界面上说明"已忽略 N 条" |
| **时间未排序** | 按原始顺序连线 → 折线来回穿插成乱麻 | **先排序**；同一时间戳应**聚合**而不是留第一条 |
| **时间缺口** | 把空洞**连起来**，图上凭空多出一段不存在的平稳期 —— 这是**撒谎**，不是美观问题 | **检测并断开**：相邻间隔超过中位间隔的 3 倍即视为缺口，**分成多段**绘制 |
| **全同值 / 单点** | `(max-min)` 为 0 → 除零 | 域退化时**居中展开**（如 `lo-1, hi+1`），绝不除零 |
| **离群值** | 自适应域被一个极端值拉扁，其余全挤成一条线 | 改用**分位数域**（如 1%–99%），或显式标注被截断的范围 |
| **点太多**（>2k） | 几万个 DOM 节点交给浏览器 | **按时间桶降采样**再画；表格仍显示原始记录 |
| **类别爆炸**（50 种） | 分类色只有 6–8 种可辨，颜色失去含义 | **Top-N + "其他"**，其余聚合；长标签截断并挂 `title` |

**三条原则**：

1. **不要假设输入的形状** —— 顺序、有限性、间隔是否均匀，都要自己验。
2. **丢数据要让人看见** —— 剔除多少条、截断了哪个范围，都写在界面上。静默丢弃比报错更糟。
3. **图形的连续性必须来自数据** —— 缺口处断开是**正确性**要求。一条连续的折线等于宣称
   "这期间一直是这样"；如果那期间根本没有采样，这个陈述就是假的。

### 顺带一条：测试器本身也要被怀疑

上面这 9 个数据集我跑了两遍。第一遍的结果里，**4 个 bug 出在测试器上而不是被测代码上**：
朴素版的诊断对象里手滑写了 `gaps: 0`，于是"未检测缺口"这条判据**永远不成立**；空集被判为
失败；乱序根本没检测；降采样后的点数报的却是降采样**之前**的值。

**判据写错会得到假通过，而假通过比失败危险** —— 失败会催你修，假通过让你以为已经验过了。
所以：**断言要能被证伪**，先确认它在坏的实现上**真的会失败**，否则它只是在重复你的假设。

### 聚合不是求和

合并同一时间桶里的多条记录时，"聚合"的正确算法取决于**这个数字物理上是怎么产生的**：

| 指标类型 | 正确做法 | 例子 |
|---|---|---|
| **累加 / 计数** | **求和** | 一天的请求数 = 各次上报之和 |
| **快照 / 状态** | **取最后一条** | 水位、库存、进度 —— 求和毫无意义 |
| **比率** | **分子分母各自聚合后再相除** | 一天的错误率 ≠ 每天错误率的平均 |

**陷阱**：计数型指标遇到**修正上报**时，求和会翻倍。数据源可能重复上报同一天的话，
求和之前要先确认；确认不了就**在界面上写明你选了哪一种**，别让它成为隐藏假设。

### 时间缺口：两条路，选一条，别都走

检测到空洞后有两种做法，它们是**互斥的**：

| 做法 | 适用 | 后果 |
|---|---|---|
| **补全为连续日历，缺口处显式置空** | 上游**按固定周期上报**（每天本该有数据） | 折线断开，"哪几天完全没数据"一眼可见 |
| **保持稀疏，用时间间隔检测缺口** | 上游**只在有事件时上报** | 折线同样断开，但**不能**补全 —— 没有数据的日子本就不该占一格 |

**判据：这一天没有记录，是"漏了"还是"本来就没有"？** 前者补全，后者不补。
选错会让图撒谎——把"没有流量"画成"数据缺失"，或反过来。

注意：**一旦补全了日历，基于时间间隔的缺口检测就永远不触发**（缺口变成了 `null` 而不是大间隔）。
两条路都实现可以，但要知道在当前模型下哪一条在生效，别留一段死逻辑还以为它在保护你。

### 不成立的值要判为不可信，而不是截断

错误数 > 请求数、进度 > 100%、负的耗时 —— 这些值**物理上不成立**。
不要 `clamp` 成看起来合理的数字（那是在伪造数据），也不要因此丢弃整条记录（其余字段可能没错）。
**保留可信的字段，把不可信的那个标为缺位**，并在界面上说明原因。

## 10. 复合图表：柱与线同图

一张图里既有柱又有线，是仪表盘里最常见的诉求，也是最容易画错的一种。

### 硬前提：两者必须同量纲

这是唯一绕不过去的一条。柱的**面积代表数量**，线的**位置代表数值** —— 要共用一条轴，
就必须是**同一种东西**。

| 柱表示 | 线表示 | 能否同图 |
|---|---|---|
| 异常次数 | 平均**次数** | ✅ 同量纲，共用一条从 0 起的轴 |
| 异常次数 | 移动平均次数 | ✅ 同上 |
| 异常次数 | **平均分**（0–100） | ❌ **量级不同** |
| 销售额 | 利润率（%） | ❌ 同上 |

**量级不同的出路只有两条**：**拆成上下两张对齐的图**（共享 X 轴），或**把线换成同量纲的量**
（比如"平均每类次数"）。**不要**加第二 Y 轴 —— 见 §6，那是画出来的相关性。

> 自检一句话：**这条线上的一个点，能不能用左边那条轴的刻度读出来？**
> 能 → 可以同图；不能 → 必须拆。

### 画法

**堆叠柱**：从 0 **累积**着往上叠，每段用累积值算上下边界；**段的先后顺序在所有柱之间保持一致** ——
否则同一颜色在不同柱里代表不同层，图例就失效了。

**折线**：数据点画在**每根柱的中心**，不是柱的边缘，否则线与柱的对应看起来会偏一格。

**命中区**：堆叠出来的段可能只有 1–2 像素高，鼠标根本点不中。**给每根柱补一个覆盖整柱高度的
透明命中矩形**，把事件挂在它上面，而不是挂在可见的段上。

### 悬停是获取数据的方式，点击只是「钉住」

★ **判据：什么都不点，能不能读到任意一个数据点的全部字段？** 能才算合格。

这一条很容易做反：把"完整读数"只挂在点击上，等于给"看数据"加了一道门槛 —— 而看数据
正是这个图表存在的理由。**悬停就该给出全部字段**（堆叠柱的三段分项、折线点的采样次数……），
**点击只负责把它固定下来**，好让你移开鼠标去别处。

### 「悬停」与「点击」的分工（详见 §8）

一句话：**悬停给全部字段，点击只负责钉住**。三处冲突必须显式定规则 ——

- **钉住优先于悬停**：钉住后移开鼠标，面板内容不变。
- **tooltip 跟不跟手要写明**：图外面板锁定钉住那条，跟手的 tooltip 显示当前悬停那条
  （"钉住的答案" vs "我正在指的东西"）。选一种。
- **键盘必须能解除钉住**，否则按方向键面板不动，用户会以为键盘坏了。

配套几件小事，少一件都像"点了没反应"：再点一次取消、点空白清除、Esc 清除、
**图外要有详情面板**（图上的高亮只说明"选了哪个"，说明不了"选的是什么"）、
同页表格的行也响应点击并同步选中。

**图例切换的边界**：全部序列都被隐藏时**自动恢复全部** —— 否则留下一张空图，用户会以为它坏了。

### ★ 给折线加面积填充，就等于声明它是数量

这是 §6 那条规则最容易踩空的地方：**折线可以从非 0，是因为它只代表位置**。
一旦你在它下面填了面积，读者看到的就变成"面积的大小"，**规则随之改变 —— 必须从 0**。

代价是真实的：日常值在 1% 左右、尖峰到 5% 的比率，从 0 起画会**被压成贴地的一条直线**，
除了尖峰什么都看不出来。

**所以二选一，别两头占**：

- **想看清波动** → 去掉面积填充，让折线自适应域；
- **想表达"占了多少"** → 保留填充，从 0 起，接受波动被压缩。

### ★ 触屏没有悬停，必须退化而不是消失

**悬停是桌面端的默认，不是唯一方式。** 触摸屏没有指针悬停；如果读数只挂在 hover 上，
手机用户的体验会退化成"必须先点一下"，甚至完全读不到数据。

**触屏上"点击即读数"是必须的**，而且此时点击**不再只是"钉住"**，它就是获取数据的方式。
判断方式：`matchMedia('(hover: none)')`，或直接监听 `touchstart`。

| 设备 | 读数据 | 钉住 |
|---|---|---|
| 有指针悬停 | 悬停 | 点击 |
| 无指针悬停（触摸） | **点击 / 轻触** | 再点一次，或点空白清除 |

### 派生序列（移动平均、累计值）要把参数说全

只说"画一条均值线"是不够的。以下每一项都会改变读者看到的东西：
**窗口大小**（7 日？）· **居中还是滞后** · **最少样本数**（样本不足时画不画）·
**在缺失处是否插值**。默认值要写进图注 —— 否则"7 日均值"是一句没有定义的话。

### 另外两件小事

- **tooltip 会遮住数据**：它跟鼠标走时会盖住右上角的柱子。要么做窄、要么遮挡严重时让位、
  要么固定在图外（详情面板就是这个思路）。选一个，别不管。
- **不明文规定的阈值都是产品决策**："错误率 ≥ 3% 算异常"不是通用规则。
  把它**写在界面上**（图注、图例、详情面板），别让它藏在代码里。

## 11. 视觉质量：从"正确"到"像设计过的"

一张图可以**完全正确、编码准确、清晰可读**，**而且看起来很业余**。

> Polish is the last 10% that signals craft and earns trust.

前面每一节都在保证"不出错"。这一节保证"看起来有人认真做过"。

### 一、排版是最大的分野

> **Type is most of what separates a pro chart from a default one.**

- **三档字号，清楚次序**：结论式标题 → 副标题 → 轴标签 → 来源行（约 19 / 13.5 / 11 px）。
  **标题说的是发现，不是图表类型**：不是「USB 异常柱状图」，而是「第 11 天欠压冲高到 27 次」。
- **最多两个字重**。把 400/500/600/700 全用上，等于没有层次。
- **标题左对齐到绘图区**，不要居中于整张图 —— 前者读起来像**有意为之**，后者像默认值。
- 全图**一个干净的无衬线字体**；默认字体若显过时，就换一个。

### 二、留白不是浪费

> Generous margins read as **confident**. **Cramped charts read as anxious.**
> **Misalignment is the most common tell of an amateur chart.**

- 卡片内边距 **20–24px**，页面外边距 **32–40px**。
- **标题、图表、详情面板、数据表对齐到同一条左边缘**。
- 柱子之间留缝（`gap ≈ 0.4`）；元素挨在一起就没有节奏。

### 三、配色：上下文压低，只留一个强调色

> Apply your house palette: **muted context, one accent for the message.**

- **所有颜色都高饱和 = 没有主次**。上下文数据用低饱和，**要说的那件事**用唯一的强调色。
- **分类色用同一色系的明度阶梯**（浅/中/深）—— 天然协调、天然色觉友好，
  而且**顺序自带含义**（浅→深 = 少→多）。
- **深色模式不是反转**：重新挑一套，降饱和、拉开明度。
- **面积越大，饱和度越低**；小色块可以更艳。

### 四、视觉层次：数据 > 坐标轴 > 网格

- **网格线淡到几乎看不见**（不透明度 ~0.05），或只在悬停时出现。
- **零基线**可以比其它网格略重 —— 它是唯一有含义的那条。
- **轴标签用最淡的一档颜色**，字号最小。一屏只有**一个**视觉焦点。

### 五、细节完成度

| 项 | 做法 |
|---|---|
| 圆角 | 柱顶 **4–6px**（1–2px 等于没有）；底部直角，让它看起来是**一根**柱而不是三个方块 |
| 过渡 | 交互变化给 **150–200ms**，不要瞬跳 |
| 浮层 | tooltip / 菜单**要有阴影和圆角**，不是裸框 |
| 选中态 | **不只换背景色** —— 加描边、放大标记点、或加指示条 |
| 数字 | **千分位**；**去掉假精度**（`94.2` 而不是 `94.23671`）；`1.24M` 优于 `1240000.0` |
| 直接标注 | **在线末端标名字**，比图例更快被读到；关键结论**直接写在图上** |
| 来源行 | 底部一行极淡小字说明数据来源 —— 这是**可信度**信号 |

### 六、数据点标记：默认不画

给折线的每个点画一个圆点，**在点少时帮助读者看清采样位置，在点多时纯属噪音**。
Datawrapper 的措辞很准：line symbols *"can even be visually overwhelming if you have lots of lines or dates."*

**判据 —— 时间间隔是否均匀？**

| 情况 | 做法 |
|---|---|
| **间隔均匀**（每小时/每天一点） | **不画点**。间隔本身没有信息量，画点只是噪点 |
| **间隔不均匀**（事件驱动、上报稀疏、混合粒度） | **画点** —— 读者必须看得出"哪里真的有采样" |
| 点数很少（< 20） | 画点也无妨，此时它不构成负担 |

这条与 §9 的缺口处理是一体的：**缺口让间隔变得不均匀，而不均匀正是画点的理由。**

### 七、直接标注的颜色要与线一致，且要能在窄屏退化

- 直接标注（线末端的名字）**用该序列自己的颜色** —— 读者的眼睛不必再回图例对照一次。
- ★ **窄屏上必须退化**：宽度不够时，线末端的标注会互相重叠或跑出画布。
  此时应**自动改为图表上方的色块图例**（或图下方）。这条**必须在实现里显式处理**，
  不是"响应式会自己搞定"。

### 八、用灰色 + 线宽 + 线型区分主次

Datawrapper 给的具体手法：*"Use colors, line width and line dashes to make your most important
values stick out. **Grey is a great color to separate what's important from what's not.**"*

- **主角线**：强调色、**较粗**（2px）
- **对照线**（均值、其他地区、历史同期）：**灰色**、**较细**（1.25px），必要时虚线
- **别用第二种强调色** —— 两个都强调等于都不强调

这也解释了为什么"加个对比数据"通常是对的（它给读者上下文），
但**前提是那条对比线必须退到背景里去**。

### 九、按最终显示尺寸检查

在 27 寸显示器上清晰的图，投到幻灯片或手机上可能读不出来。**按它实际被看到的大小来设计。**

### 七、不要过度打磨

> **Polish serves communication, it isn't the goal.** 排版完美却做了错误比较的图，依然是错的。
> **探索用的图根本不需要打磨。**

顺序不能反：**先诚实，再编码，再清晰，最后才是打磨。**

## 12. 交付前自检

每节都给了判据，这里**只列最容易漏掉的**。**三个必做**不能跳：

1. **真机滚动一遍**（§1）—— 不是看一眼，是真的滚。列宽 / 行高 / 滚动条位置都不许动。
2. **喂一批脏数据**（§9）—— `NaN`、乱序、全同值、空集、缺口各来一个。不抛异常，并如实报告丢了几个。
3. **按最终显示尺寸看**（§11）—— 幻灯片或手机。27 寸上清晰不代表它能用。

其余七条：

- [ ] 列宽是**显式**的吗？`table-layout: fixed` 了吗？数字列有 `tabular-nums` 吗？
- [ ] **容器高度在数据到达前就固定**了吗？（加载不该推动页面）
- [ ] 每个 `<th>` 都有 `scope="col"` 吗？—— `grep '<th' | grep -v 'scope='` 应当无输出
- [ ] 悬停就能读到**全部字段**吗？（不必点击；触屏上点击**必须**是读数据的方式）
- [ ] 所有视图都从**同一个**过滤状态派生吗？（各自过滤迟早不一致）
- [ ] 用参照标准的 **Grep Signatures** 扫过一遍吗？
- [ ] 深浅两套主题都验过吗？
